# Codebook for coders 

**First: what position does the actor take?** Code the actor's stance towards the Commission's simplification agenda as expressed in these example: 

| Label | Use when the actor...|
| `pro_simplification` | wants an obligation's *procedural route* eased — delays, phase-ins, streamlined steps, fewer duplicate filings — without arguing the underlying protection should be lower |
| `pro_deregulation` | wants the *substantive level* of obligation or protection reduced or removed |
| `anti_simplification` | opposes easing the procedure, e.g. argues agreed deadlines should hold |
| `anti_deregulation` | opposes lowering the substantive level of protection |
| `neutral_ambivalent` | acknowledges both sides, or raises a request that takes no stance on simplification |

The simplification / deregulation distinction is the hardest call. The rule is:
Does the actor want a different route to the same obligation (simplification), or a smaller obligation (deregulation)? 
e.g., Asking to postpone high-risk requirements until standards exist is simplification. 
e.g., Asking to delete the Commission's power to impose common specifications is deregulation.
When you cannot tell, choose the more conservative reading (simplification) and note it.

**Second: what kind of reason does the actor give?** 
Code the *logic used to justify* the position (not the position itself) and *not* whether you find it convincing. 
Note: A pro- and an anti- actor can use the same type of reason.

---

*Eight argument types* categories. Code the **logic the actor uses to justify its position**, not the position itself and not whether the reasoning is persuasive.

Deliberately no example quotes are given here: quotes drawn from the corpus could give away the original coding of the snippets you are about 
to read. The "look for" cues below are *generic*.

---

Argument types:

1. *Regulatory coherence* as an argument type emerging from text mentioning, for example, a need to reduce fragmentation, harmonization across regulations, or to avoid duplication in regulation
2. *Technical feasibility* as an argument type emerging from text mentioning, for example, that timelines are too tight, standards are not ready, or that regulatory implementation is complex 
3. *Competitiveness* as an argument type emerging from text mentioning, for example, that regulatory burden harms EU competitiveness, SMEs, or R&D 
4. *Legal certainty* as an argument type emerging from text mentioning a need for clear, predictable compliance rules 
5. *Rights protection* as an argument type emerging from texts mentioning, for example, protecting consumers, safety, or fundamental rights 
6. *Industry self-regulation* as an argument type emerging from text mentioning, for example, maintaining compliance reliance on industry-led standardization 
7. *Improve governance* as an argument type emerging from text mentioning, for example, the need for more resources for regulatory bodies
8. *Inclusive governance* as an argument type emerging from text mentioning, for example, a need to include representation of a wider range of stakeholders in AI governance 
---

## If two types seem to apply

Pick the one carrying the **main weight of the justification** — the reason the actor
would give first if pressed. Note the runner-up in `notes_optional`.
